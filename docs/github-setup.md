# Настройка GitHub

PRD, раздел «Настройка GitHub»: `main` защищена, прямые коммиты запрещены, CI обязателен.

## Защита `main`

Настройки хранятся в [`.github/branch-protection-main.json`](../.github/branch-protection-main.json)
и применяются одной командой (нужны права администратора репозитория):

```
gh api -X PUT repos/AESFUI/cube-snake/branches/main/protection --input .github/branch-protection-main.json
```

Проверить текущее состояние:

```
gh api repos/AESFUI/cube-snake/branches/main/protection
```

| Настройка | Значение | Зачем |
| --- | --- | --- |
| Изменения только через PR | да, 0 обязательных одобрений | Claude Code работает под тем же аккаунтом, а GitHub не даёт автору одобрить свой PR. Решение человека — это слияние |
| Обязательные проверки | `build (debug)`, `build (release)` из GitHub Actions (`app_id` 15368) | Красный или незавершённый CI блокирует слияние |
| Ветка должна быть актуальной (`strict`) | нет | Меньше лишних прогонов. Риск: два PR, зелёные относительно старого `main`, вместе могут его сломать — это покажет CI на `main` после слияния. Для одного разработчика приемлемо |
| Правила для администраторов (`enforce_admins`) | да | Владелец репозитория — администратор; без этого флага защиту обходят и человек, и Claude Code |
| Force-push и удаление `main` | запрещены | История `main` не переписывается |

## Если меняются имена заданий CI

Имена обязательных проверок совпадают с `name:` заданий в `.github/workflows/ci.yml`.
Защита применяется к GitHub отдельно от слияния, поэтому порядок такой:

1. Claude Code в том же PR меняет `ci.yml` и `.github/branch-protection-main.json`. Сам защиту не меняет
   (запрет в `CLAUDE.md`; исключением было только её первое включение по #3).
2. Когда CI с новыми именами зелёный, человек непосредственно перед слиянием применяет защиту командой выше
   и сливает PR. Если применить раньше — встанут остальные открытые PR; если позже — встанет сам этот PR.
