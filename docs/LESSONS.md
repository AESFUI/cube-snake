# Журнал уроков

После каждой задачи — одна запись (SC-5). Новые записи добавляются в конец.

Шаблон:

```markdown
## <дата> · #<issue> · <название>
Запрос: что и как было поставлено.
Результат: что сделано с первой попытки, сколько было правок.
Промахи ИИ: что пошло не так и кто это заметил.
Урок: что изменить в следующий раз.
Правка CLAUDE.md: да/нет, какая.
```

## 2026-11-05 · #1 · Репозиторий и документы процесса
Запрос: по стартовому промпту из PRD — предложить CLAUDE.md, issue этапа 0 и вопросы; после ответов создать milestone, issue и взять #1.
Результат: документы созданы с первой попытки, ревьюер критичных замечаний не нашёл. Одна правка по ревью: пункт «человек проверил визуальные изменения» в шаблоне PR и чтение файлов ревьюером из head-коммита PR.
Промахи ИИ: создание публичного репозитория заблокировал классификатор прав — правильно, это необратимое действие наружу; репозиторий создал человек. Ревьюер заметил, что «только чтение» не обеспечено технически (Bash не ограничен) и что правообладатель в LICENSE взят из git-identity без подтверждения.
Урок: публичные и необратимые действия заранее отдавать человеку готовой командой. Не подставлять юридически значимые данные (правообладатель) без явного подтверждения. Агенты из `.claude/agents/`, созданные в сессии, доступны только в новой сессии.
Правка CLAUDE.md: нет.

## 2026-11-05 · #2 · Каркас CMake, тесты Catch2 и CI
Запрос: пресеты debug/release, статические библиотеки модулей, /W4 /WX, /MT, Catch2, CI с артефактом. Перед кодом — план (архитектура), человек одобрил с отступлением: /W4 /WX только для нашего кода.
Результат: локально собралось с первой попытки. Правок: тест с кириллическим именем (1), раннер CI (1), замечания ревью (1 коммит).
Промахи ИИ: (1) кириллическое имя TEST_CASE — ctest на Windows передаёт фильтр в ANSI, тест «падал», хотя проходил; заметил ИИ локально. (2) PRD требует одновременно VS 2022 и windows-latest, а windows-latest уже windows-2025-vs2026; риск ИИ предвидел, но не проверил до первого прогона — заметил CI. (3) Ревьюер нашёл, что ctest без noTestsAction=error проходит при нуле тестов, и что описание PR устарело после правки раннера.
Урок: перед CI-конфигурацией проверять фактический состав образа раннера. После каждой правки по ходу PR сверять описание PR с кодом. Тестовые проверки делать «громкими»: ноль тестов — ошибка.
Правка CLAUDE.md: да — имена тестов Catch2 латиницей; правила project_options и путей заголовков.

## 2026-11-05 · #3 · Защита ветки main
Запрос: включить защиту main через gh api — только PR, обязательный CI, без force-push; без обязательных одобрений.
Результат: защита применена с первой попытки, настройки сохранены в репозитории. Прямой push отклонён (GH006); PR BLOCKED, пока CI идёт, и CLEAN после зелёного. Одна правка по ревью.
Промахи ИИ: в описании PR остался заполнитель вместо результата проверки — заметил ревьюер. Инструкция «обновить защиту в том же PR» противоречила запрету в CLAUDE.md и не учитывала порядок применения — заметил ревьюер. Сам ИИ заметил, что без enforce_admins защиту обходит администратор, а значит и Claude Code под тем же аккаунтом.
Урок: настройки, которые применяются вне git, описывать с порядком действий и тем, кто их применяет. Не оставлять в описании PR заполнители «будет ниже» — дописывать сразу по факту. Проверку «нельзя слить» делать по mergeStateStatus, а не попыткой слияния.
Правка CLAUDE.md: нет.
