# 0001. CI на образе windows-2022 вместо windows-latest

Дата: 2026-11-05 · Статус: принято

## Контекст

PRD («Стек») требует одновременно «C++20, MSVC из Visual Studio 2022» и «CI: GitHub Actions,
`windows-latest`». На ноябрь 2026 `windows-latest` — образ `windows-2025-vs2026`, в нём только
Visual Studio 2026. Генератор `Visual Studio 17 2022` там не находит студию, CI падает на
конфигурации (PR #8).

## Решение

CI запускается на `runs-on: windows-2022`. Стек из PRD не меняется: локально и в CI один и тот же
компилятор VS 2022 и генератор `Visual Studio 17 2022` из `CMakePresets.json`.

## Альтернативы

- Перейти на VS 2026 везде (`Visual Studio 18 2026`, `windows-latest`) — меняет стек PRD и требует
  установки VS 2026 локально.
- Генератор Ninja с любой найденной студией — разные версии компилятора локально и в CI,
  сборка только из Developer PowerShell.

## Последствия

- Отступление от PRD только в строке «CI»; остальной стек без изменений.
- Когда GitHub объявит вывод `windows-2022` из обращения, нужно новое решение (вероятно, переход
  на VS 2026 целиком) отдельным ADR.
