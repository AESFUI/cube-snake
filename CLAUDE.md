# CLAUDE.md — Змейка на кубе

Требования: `docs/PRD.md` — источник истины. Каждая задача ссылается на ID (`FR-n`, `NFR-n`, `SC-n`).
Журнал уроков: `docs/LESSONS.md`. Архитектурные решения и новые зависимости: `docs/adr/`.

## Сборка и проверка (Windows, VS 2022, генератор «Visual Studio 17 2022»)

```
cmake --preset debug   && cmake --build --preset debug   && ctest --preset debug
cmake --preset release && cmake --build --preset release && ctest --preset release
pwsh .github/scripts/check-static-crt.ps1 build/release/bin/Release/cube_snake.exe
```

Исполняемые файлы: `build/<preset>/bin/<Debug|Release>/` — `cube_snake.exe`, `tests.exe`.
CI (`.github/workflows/ci.yml`) повторяет эти шаги и выкладывает `cube_snake.exe` артефактом.

## Модули и зависимости

`app → render → view → core`. Обратных и боковых связей нет.

- `core` — правила игры. Только стандартная библиотека C++, без `<windows.h>` и DirectX.
- `view` — читает состояние `core`, считает кадр (камера, позы). Без D3D.
- `render` — Direct3D 11, рисует кадр из `view`.
- `app` — `WinMain`, окно, ввод, игровой цикл.

Нарушение направления — замечание ревью.

## Стиль

- C++20, MSVC, `/W4 /WX`, статический CRT `/MT`.
- Понятные имена, комментарий у неочевидной математики, функции до ~50 строк.
- COM-объекты только через `Microsoft::WRL::ComPtr`.
- Логика детерминирована: тик и зерно случайных чисел передаются снаружи.
- Флаги компиляции — через цель `project_options` (`cmake/ProjectOptions.cmake`); каждая наша цель линкует её `PRIVATE`.
- Заголовки модуля — в `src/<модуль>/include/<модуль>/`, подключаются как `"<модуль>/файл.hpp"`.
- Имена тестов Catch2 — латиницей: ctest на Windows передаёт фильтр в ANSI, кириллица не находится.

## Процесс

1. Issue → ветка `issue-<N>-<кратко>` → коммиты Conventional Commits
   (тип по-английски, описание по-русски: `feat: окно Win32`).
2. Если задача затрагивает архитектуру — короткий план и ждать подтверждения.
3. PR по шаблону → зелёный CI → ревью агентом `reviewer` → исправления.
   Отчёт ревьюера публикую в PR комментарием «Ревью агента reviewer» без правок.
4. Черновик записи в `docs/LESSONS.md` — в том же PR.
5. Решение и слияние — только человек.

Если требование неоднозначно или противоречит реальности — остановиться и спросить.

## Запреты

- Не сливать PR, не пушить в `main`, не менять защиту ветки.
- Не ослаблять, не отключать и не удалять тесты и проверки ради зелёного CI.
- Не выходить за рамки issue и текущего этапа. Найденное по пути — в новый issue.
- Не добавлять зависимости без ADR.
